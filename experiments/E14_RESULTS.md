# E14 — Replication of E13

## Status

Completed successfully on 2026-10-07.

## Frozen design

- 18 Python tasks
- 20 runs per task
- 360 paired candidates
- generator model: `gpt-4o-mini`
- repair model: `gpt-4o-mini`
- exact same raw candidate evaluated before BRS
- deterministic hidden tests
- maximum one repair attempt
- full hidden-test revalidation after repair

## Main results

| Metric | Raw | BRS final |
|---|---:|---:|
| Passing cases | 308/360 | 347/360 |
| Failing cases | 52/360 | 13/360 |
| Pass rate | 85.56% | 96.39% |
| 95% Wilson CI | 81.55%–88.81% | 93.92%–97.88% |

Observed absolute gain:

- **+39 passing cases**
- **+10.83 percentage points**
- paired bootstrap 95% CI: **+7.78 to +14.17 percentage points**

## Paired outcomes

| Transition | Cases |
|---|---:|
| RAW FAIL → BRS PASS | 39 |
| RAW PASS → BRS FAIL | 0 |
| RAW PASS → BRS PASS | 308 |
| RAW FAIL → BRS FAIL | 13 |

There were no observed degradations.

The exact two-sided McNemar result was:

`p = 3.637978807091713e-12`

Within this frozen benchmark, the paired improvement is therefore highly inconsistent with a no-difference outcome under the McNemar null.

## Task-level observations

Most tasks were already near ceiling. The bulk of the measurable gain came from a smaller subset:

- `T14`: raw 2/20 → BRS 20/20 (**+18**)
- `T15`: raw 0/20 → BRS 19/20 (**+19**)
- `T07`: raw 19/20 → BRS 20/20 (**+1**)
- `T13`: raw 19/20 → BRS 20/20 (**+1**)

Two task families remained notable:

- `T01`: 1 raw failure remained unresolved after repair.
- `T18`: 11 raw failures remained unresolved after repair.

This heterogeneity matters: BRS did not make every failure repairable. It detected the failures and blocked unresolved cases.

## Interpretation

E14 replicates the direction of E13 at substantially larger scale.

On 360 paired candidates generated by the same model, BRS increased hidden-test pass rate from **85.56% to 96.39%**, an observed gain of **10.83 percentage points**.

The paired bootstrap 95% interval for the gain was **7.78–14.17 percentage points**, and there were **39 improvements versus 0 degradations**.

No unsafe release was observed. Candidates that still failed after one repair attempt remained blocked.

This result supports a narrower claim:

> On this frozen synthetic Python benchmark, using BRS to detect failures, provide localized evidence to the same model, and require full revalidation materially improved functional pass rate while preserving fail-closed behavior.

## Important limitations

This does **not** establish universal reliability or general cross-domain effectiveness.

Limitations include:

- synthetic benchmark;
- one model family;
- fixed set of 18 tasks;
- repeated samples from the same task templates;
- one repair attempt only;
- provider randomness not explicitly seeded;
- no external human-authored benchmark;
- no independent replication by another team.

The statistical intervals describe this benchmark sampling process, not all AI-generated software.
